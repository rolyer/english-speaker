## 整理目的

1. **清理根目录**: 将 AI 生成的临时文档从根目录移走，保持根目录整洁
2. **分类管理**: 将相关文档集中管理，便于查找和维护
3. **建立索引**: 创建 README 文件，方便快速定位所需文档
4. **规范化**: 统一文档管理规范，便于后续维护

## 使用建议

### 查找文档
1. 先查看 `docs/README.md` 了解文档结构
2. 根据需求查看 `docs/ai/README.md` 中的分类索引
3. 使用文件名关键词搜索（如 FIX, FEATURE, SETUP 等）

### 添加新文档
1. 核心功能文档放在 `docs/` 根目录
2. AI 生成的实现细节文档放在 `docs/ai/`
3. 更新相应的 README.md 索引

### 文档归档
- 过时的文档可以移动到 `docs/ai/archive/` 子目录
- 保留最新版本的文档在主目录

## 后续维护

### 定期整理
- 每月检查一次文档，删除或归档过时内容
- 合并重复或相似的文档
- 更新索引文件

### 文档命名规范
- `*_FIX.md` - 问题修复文档
- `*_FEATURE.md` - 功能实现文档
- `*_SETUP.md` - 配置设置文档
- `*_SUMMARY.md` - 总结文档
- `*_DEBUG.md` - 调试文档
- `QUICK_*.md` - 快速开始/测试文档

### 版本控制
- 使用 Git 跟踪文档变更
- 重要文档变更应该提交 commit
- 在 commit message 中说明文档变更内容
